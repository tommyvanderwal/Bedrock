# Exporters (node_exporter + vm_exporter)

Every node runs two Prometheus-style exporters. `bedrock-vmagent` on each node
scrapes both every 10 s (per the `node` / `libvirt` jobs in
`/opt/bedrock/scrape.yml`) and remote-writes to the cluster's VictoriaMetrics
backends. The scrape file lists every node and is regenerated by the mgmt master
(`mgmt/app.py:write_scrape_config`) whenever the node set changes.

## node_exporter (port 9100, job `node`)

Stock Prometheus `node_exporter` v1.8.2. Emits standard host metrics:

- `node_cpu_seconds_total` — per-CPU busy time (cpu %, used for load)
- `node_memory_*` — MemTotal/MemAvailable (memory %)
- `node_network_*_bytes_total` — per-NIC RX/TX counters
- `node_disk_*` — per-device IOPS, latency, throughput
- `node_load1` / `node_load5` / `node_load15`
- `node_uname_info`, `node_boot_time_seconds` — kernel + uptime

`node-exporter.service` (`installer/configs/systemd/node-exporter.service`):

```ini
[Unit]
Description=Prometheus node_exporter
After=network.target

[Service]
Type=simple
User=root
ExecStart=/opt/bedrock/bin/node_exporter --web.listen-address=:9100
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

Source binary: `installer/binaries/node_exporter`, fetched to
`/opt/bedrock/bin/node_exporter` by `installer/lib/exporters.py:install()`.

## vm_exporter (port 9177, job `libvirt`)

A ~190-line Python exporter (`mgmt/vm_exporter.py`, shipped as
`installer/binaries/vm_exporter.py`). Python stdlib only (`http.server`,
`subprocess`, `json`). Serves `/metrics` on `0.0.0.0:9177`; any other path is
404. Emits bare metric lines under a single comment header — no per-metric
`# HELP` / `# TYPE`.

It runs three collectors, parsing local command output each scrape:

| Collector | Command | Series prefix |
|---|---|---|
| `collect_vm_metrics` | `virsh domstats --cpu-total --balloon --block --interface --state --raw` | `bedrock_vm_*` |
| `collect_drbd_metrics` | `drbdsetup status --json` | `bedrock_drbd_*` |
| `collect_thinpool_metrics` | `lvs … --select 'lv_attr=~"^t"'` (thin pools) | `bedrock_thinpool_*` |

Example output:

```
# Bedrock VM and DRBD metrics exporter
bedrock_vm_state{vm="webapp1"} 1
bedrock_vm_cpu_time_ns{vm="webapp1"} 31694058000000
bedrock_vm_memory_current_kb{vm="webapp1"} 2097152
bedrock_vm_disk_write_reqs{vm="webapp1",disk="0"} 12
bedrock_vm_net_rx_bytes{vm="webapp1",iface="0"} 88421
bedrock_drbd_role{resource="vm-webapp1-disk0",role="Primary"} 1
bedrock_drbd_disk_state{resource="vm-webapp1-disk0",minor="1000",state="UpToDate"} 1
bedrock_drbd_out_of_sync_kb{resource="vm-webapp1-disk0",peer="bedrock-sim-2"} 4096
bedrock_thinpool_data_percent{vg="bedrock-vg",pool="thinpool"} 42.10
```

Notable series:

- VM: `bedrock_vm_state`, `bedrock_vm_cpu_time_ns`, `bedrock_vm_memory_{current,maximum}_kb`,
  `bedrock_vm_disk_{read,write}_{reqs,bytes}` + `_time_ns`, `bedrock_vm_disk_flush_*`,
  `bedrock_vm_net_{rx,tx}_{bytes,packets}` (labels `vm`, `disk`, `iface`).
- DRBD: `bedrock_drbd_role`, `bedrock_drbd_disk_state`, `bedrock_drbd_connection`,
  `bedrock_drbd_{written,read,sent,received}_kb`, `bedrock_drbd_out_of_sync_kb`,
  `bedrock_drbd_peer_disk_state`, `bedrock_drbd_al_writes` (labels `resource`,
  `minor`, `peer`, `state`). State/role/connection series carry the value in a
  label and the metric value is always `1`.
- Thin pool: `bedrock_thinpool_size_bytes`, `bedrock_thinpool_data_percent`,
  `bedrock_thinpool_metadata_percent` — the dashboard warns above 80 %.

`vm-exporter.service` (`installer/configs/systemd/vm-exporter.service`):

```ini
[Unit]
Description=Bedrock VM/DRBD exporter
After=libvirtd.service
Wants=libvirtd.service

[Service]
Type=simple
User=root
ExecStart=/usr/bin/python3 /opt/bedrock/bin/vm_exporter.py
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

## Deployment

Both units are installed on every node by `installer/lib/exporters.py:install(repo)`,
called from the cluster-init saga's `install_exporters` step
(`bedrock_d/install/cluster_init.py`) on the first node and the node-join saga's
`install_exporters` step (`bedrock_d/install/node_join.py`) on every subsequent
node. `install()` is idempotent — it skips `node_exporter` if already on disk,
always refreshes `vm_exporter.py`, writes the two unit files, and runs
`systemctl enable --now node-exporter vm-exporter`.

```
install(repo):
  mkdir -p /opt/bedrock/bin
  curl <repo>/binaries/node_exporter   -> /opt/bedrock/bin/node_exporter   (chmod 755, skip if present)
  curl <repo>/binaries/vm_exporter.py  -> /opt/bedrock/bin/vm_exporter.py  (chmod 755)
  # also fetch the obs binaries (vmagent, vlagent, vmbackup, vmrestore,
  # victoria-metrics, victoria-logs) so any node can be promoted to a
  # backend slot; observability.py owns their units. Skip if already
  # present (>1 MB). curl failures here only warn.
  write /etc/systemd/system/node-exporter.service
  write /etc/systemd/system/vm-exporter.service
  systemctl daemon-reload
  systemctl enable --now node-exporter vm-exporter
```

## Why vm_exporter, not a libvirt-exporter project

- DRBD and libvirt metrics land in the same scrape from one process; most
  libvirt exporters don't surface DRBD at all.
- Stdlib-only Python: no Go toolchain, no extra deps, no specific libvirt
  connection mode to configure.
- ~190 lines anyone can read; a new metric is a couple of lines in the matching
  collector.

## Reading metrics directly

```bash
curl http://<node>:9100/metrics | grep node_load
curl http://<node>:9177/metrics | grep bedrock_drbd_role

# Via a VictoriaMetrics backend:
curl 'http://<vm-backend>:8428/api/v1/query?query=up{job="libvirt"}'
```

## Failure modes

| Symptom | Cause | Recovery |
|---|---|---|
| `up{job="node"}=0` for a host | node_exporter down | `systemctl status node-exporter`; `journalctl -u node-exporter`. |
| `up{job="libvirt"}=0` for a host | vm_exporter down, or libvirtd down | `systemctl status vm-exporter libvirtd`. |
| vm_exporter responds but DRBD metrics missing | `drbdsetup status --json` needs the kernel module | `modprobe drbd`; `systemctl restart vm-exporter`. |
| Port collision on 9100 / 9177 | a stray exporter process | `ss -tlnp \| grep 9100`; stop the stray. |

## Extending vm_exporter

Add a metric in the matching collector in `mgmt/vm_exporter.py`:

```python
def collect_vm_metrics():
    lines = []
    ...
    lines.append('bedrock_vm_new_metric{vm="%s"} %s' % (current_domain, value))
    return lines
```

Mirror the change into `installer/binaries/vm_exporter.py` (the fetch source).
Nodes pick it up on the next `exporters.install` run; the `/metrics` endpoint is
unchanged, so no scrape-config edit is needed.
